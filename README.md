# 历史雨量档案 · 双录与复核

一个可启动的 Flask + SQLite 网页系统，用于把纸质日雨量卡片录入历史观测库。系统包含双人独立录入、扫描原图复核、裁定失效与重新核对、核定 CSV 导出，并提供 Docker Compose、四张样卡和三个演示账号。

## 快速启动

```bash
docker compose up --build
```

浏览器打开 <http://localhost:8000>。首次启动会自动建库、载入演示账号和示例卡片，数据保存在 Compose 命名卷 `archive-data` 中。


## 演示路径

样卡预置了四种状态，其中两张卡的扫描图在扫描时挂反（本演示的主线场景）：

| 卡片 | 当前挂载原图 | 原图实际内容 | 预置状态 |
| --- | --- | --- | --- |
| `YC-1986-0714` | 样卡 001 | 30501200 / 1986-07-14 / 42.5 mm | 两份均未录入 |
| `YC-1986-0715` | 样卡 003（**挂反**） | 应为样卡 002：30501210 / 1986-07-15 / 31.0 mm | 两份有出入：甲填 31，乙填 13 |
| `YC-1986-0716` | 样卡 002（**挂反**） | 应为样卡 003：30501220 / 1986-07-16 / 0.0 mm | 两份一致，表面已核定 |
| `YC-1986-0717` | 样卡 004 | 30501230 / 1986-07-17 / 88.0 mm | 甲已录入，等待乙 |

1. **试双录**：甲乙分别登录，打开 `YC-1986-0714`，填写同一组值（如 `42.5` 与 `42.50`）。复核员工作台会显示“两份一致 · 已核定”，CSV 中立即出现该卡。
2. **试换图（主线）**：复核员在工作台“挂反扫描图互换”区勾选 `YC-1986-0715` 与 `YC-1986-0716`，进入对照确认页并排核对两张原图中的档案号，确认后一次提交完成互换。两张卡**同时换图并退回待录**：卡号与录入员不变，旧录入留档停用（不再预填、不参与核定），旧裁定保留并标记“换图退回待录”失效，两卡立即从 CSV 消失。
3. **试旧页拦截**：换图前若录入员或复核员的页面一直开着，换图后在旧页面提交录入或裁定，系统返回 **409 并提示刷新、不写入**；刷新后页面显示换过来的原图（图片 URL 带原图版本号且 `Cache-Control: no-store`），录入表单为空，需要照新图重录。
4. **试重录与重核定**：甲乙按新原图各录一份（如 `31` 与 `13`），产生冲突后复核员重新打开卡片、对照新原图选甲并核定，CSV 中该卡按新版本恢复；裁定记录与换图记录均留痕。
5. **试裁定失效**：保持复核员的旧页面不刷新，让乙登录改填 `YC-1986-0715`（即使仍填 `13.0`）。保存即产生新版本，原裁定立即失效，该卡从 CSV 消失；旧页面上提交裁定会收到 **409 拒绝**，并提示以最新两份重新核对。
6. **试上传**：复核员在工作台上传一张 PNG/JPEG/GIF/WebP 扫描图，选择两位录入员，即可建立新的双录任务。

## 关键业务规则

- **双人独立录入**：每张卡片固定分配给两位不同的录入员。录入员只能查看和改填自己的那一份，页面、查询和写接口都不会暴露另一位录入员的值。
- **版本化录入**：每次保存都会让 `revision` 加一，即使填写内容没有变化。
- **原图版本与换图**：每张卡带 `image_version`。复核员可把正好两张卡的扫描图原子互换；卡号与录入员保持不变，仅交换 `image_filename`，两卡原图版本同时加一。换图在单事务内完成：旧录入按 `entries.image_version` 留档停用（不预填、不参与核定），两卡退回待录，有效裁定以 `voided_reason = 'image_swapped'` 标记失效并永久留痕，换图动作写入 `image_swaps` 审计表。
- **按原图版本隔离的录入**：唯一约束为 `(card_id, clerk_id, image_version)`，换图后的新一轮双录从第 1 版重新开始，与旧原图下的录入互不覆盖。
- **自动核定**：当前原图版本下最新两份录入的站号、ISO 观测日、规范化雨量完全一致时，系统自动核定，无需复核。
- **原图裁定**：不一致时只能由复核员选择当前两份中的一份。裁定记录绑定甲、乙两份录入的 `entry id` 与 `revision`，并同时绑定当时的 `image_version`，保存快照值。
- **裁定失效**：任一录入员保存或卡片换图后，该卡所有有效裁定立刻标记失效，历史记录保留用于审计；系统按当前原图版本的最新两份重新计算，可能变为“两份一致”或继续“待复核”。
- **拒绝旧页面写入（乐观并发）**：录入表单、裁定表单、换图确认页都携带页面所见的 `image_version`（裁定另带两份录入的 id/版本号）。提交时在 SQLite `BEGIN IMMEDIATE` 写锁内再次校验：原图已更换或录入已改填，则返回 409、提示刷新且不写入任何数据。刷新后图片 URL 的版本号变化并配合 `Cache-Control: no-store`，保证看到换过来的原图。
- **CSV 只含当前核定**：下载时实时重算每张卡的状态，只输出当前原图版本下已核定（两份一致或有效复核裁定）的卡片，每卡恰好一行。失效裁定、待复核、缺一份录入、换图后尚未重录的卡都不会出现在 CSV 中。

CSV 列：

```text
card_no,station_no,observation_date,rainfall_mm,verification,verified_at
```

`verification` 为 `double_entry_agreement` 或 `reviewer_adjudication`。

## 项目结构

```text
app.py                    Flask 应用、路由、校验、核定状态机、换图与旧库迁移
schema.sql                SQLite 表与索引（含原图版本、换图审计表、版本化录入唯一索引）
templates/                登录、录入、复核、换图确认界面
static/style.css          页面样式
sample_cards/             四张可展示的 SVG 样卡
tests/test_app.py         业务规则、换图流程与越权访问测试
Dockerfile
docker-compose.yml
```

## 配置

Compose 可通过环境变量或 `.env` 调整：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_PORT` | `8000` | 宿主机端口 |
| `SECRET_KEY` | 演示默认值 | Flask 会话签名密钥；对外部署前务必更换 |
| `SESSION_COOKIE_SECURE` | `0` | HTTPS 部署时设为 `1` |

数据库与上传图保存在容器内 `/app/data`，由命名卷持久化。扫描图限制 16 MB；上传仅凭文件签名接受 PNG/JPEG/GIF/WebP，不接受可执行脚本型 SVG。

演示密码写死于初始化数据，仅适合本地试用。正式使用前应改为真实账号体系并启用 HTTPS。
